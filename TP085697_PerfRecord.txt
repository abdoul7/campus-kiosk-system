*Insert at beginning complexity note:
The assignment's linked-list insertion at the head is O(1) because it only changes the new node's next pointer and the head pointer. In this implementation, the public insert function also performs the required duplicate Student ID validation before inserting. That duplicate check uses a linear scan, so the full measured public operation can show O(n) growth even though the actual head-link step is O(1).

The memory complexity is O(n) because each new student record creates one additional node. Each operation uses O(1) extra working space because it only uses a few pointer variables such as current, previous, and temp.

Key Big-O Justification
A singly linked list does not support random access, so every operation that needs to find a record or a position must start from head and follow next pointers one node at a time. Therefore, search, delete, count, display, insert at end, and insert at a specified position are O(n). Insert at beginning is O(1) for the pointer update itself, while the submitted public function also validates duplicate Student IDs, which adds a linear scan before the insert. Binary Search and CGPA sorting are not applicable to this linked-list part.
